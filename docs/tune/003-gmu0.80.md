## Boot — FAIL (watchdog kill, unified-memory exhaustion)

Timeline (host clock, orcus):

- 02:36:09 watchdog start (floor=6 GiB, container=vllm-fn)
- 02:47:03 PLE offload registered (1 layer, tp_size=2) — PLE side fine
- 02:48:09 `Available KV cache memory: 24.74 GiB` / **`GPU KV cache size: 3,120,831 tokens`**
  (max concurrency 262144-tok: 11.91x) — weights 131/131 loaded, KV sized
- 02:48:19 flashinfer autotune starts; unified-memory pool collapses
  (MemAvailable 30493 -> 18249 -> **6110 MiB** in 10s, host total 124609 MiB)
- **02:48:19 memwatch: `MemAvailable=6110 MiB < floor -> docker kill vllm-fn`; killed 02:48:21**
- orcus container `Exited (137)`; warda rank-1 log: TCPStore `Broken pipe` cascade
  (peer = orcus head gone) — cascade, not an independent warda fault

Root cause: on the DGX Spark unified-memory pool, GMU 0.80 reserved ~0.81M extra
fp8 KV tokens (3.12M vs 2.30M at 0.75) on top of weights/PLE; the combined
footprint exhausted host RAM during post-KV-sizing warmup (flashinfer autotune +
CUDA graph capture) and tripped the MEMWATCH_MIN_GIB=6 watchdog floor. The watchdog
did exactly what it is for — this is a **genuine capacity limit, not a software bug**.
